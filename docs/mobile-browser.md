# 모바일 브라우저 확대·길게 누르기·크기 안정화 — 2026-11-08

사용자는 iOS/Safari 여부는 불명확하지만 자동 확대, 길게 누르기 복사 메뉴, UI 크기 변화를 보고했다. 실제 아이폰 증상을 재현했다고 단정하지 않고 브라우저 기본 동작과 코드의 높이 의존성을 수정한다.

게임 영역은 viewport 배율1, touch-action manipulation, Safari 텍스트 자동 확대 차단, 선택/드래그/컨텍스트 메뉴 차단을 사용한다. 같은 대상의 연속 터치, Safari gesture 이벤트와 두 손가락 브라우저 확대를 막는다. 캔버스/조작키의 Pointer Events는 유지한다. 텍스트·이메일·비밀번호·닉네임 입력은 선택/복사/붙여넣기를 허용하며 터치 기기의 입력 글자는16px 이상이다. 한 손가락 메뉴 스크롤도 유지한다.

visualViewport의 배율1일 때 실제 가용 너비·높이·오프셋으로 앱과 대화상자를 맞춘다. 접근성 확대를 허용하는 브라우저에서 배율이 변해도 그 수치로 게임 UI를 재축소하지 않는다. 태블릿은 화면의 짧은 변600px 이상으로 판단하여 주소창/키보드 높이로 휴대폰 크기로 바뀌지 않는다. 넓은 휴대폰은 작은 조작키를 유지한다. 태블릿 조작키는 안정 뷰포트 단위svh를 사용한다.

기존 모든 resize 입력reset·메뉴닫기를 너비 변경 시로 제한한다. 주소창의 높이 변화는 이동 중인 손가락과 열린 메뉴를 유지하며, 실제 방향 전환/너비 변경과 blur/visibilitychange는 여전히 입력을 해제한다. 엔진/카메라 크기 갱신은 한 애니메이션 프레임으로 합친다.

검증: 수정 전에 게임 컨텍스트 메뉴 차단과 높이만 바뀔 때 이동 유지 검사가 각각 실제 기대 동작으로 실패했다. 수정 후 해당 검사와 텍스트 편집 예외·터치 확대/스크롤 분리·배율 변화 시 레이아웃 유지 검사가 통과했다. Chromium과 Linux WebKit에서844×390,915×412,1024×768의 입력16px·선택차단/편집예외·배율1·태블릿분류·이동유지를 확인했다. Chromium CDP에서 실제 터치 메뉴 스크롤과 두 손가락 확대 차단을 검사했다. 기존 여섯 화면 조작키/HUD 배치, PC/모바일 DOM 흐름도 통과했다. 실제 게임 초기화와 시뮬레이션을 사용하는 Chromium 검사에서 태블릿의 이동·사격 동시 터치, 사격 손가락 해제 후 이동 유지, 휴대폰/태블릿/PC의 높이 변화 중 메뉴 유지와 설정창 열기/닫기를 통과했다. 이 검사는 렌더링만 대체하므로 GPU/시각/성능 검사가 아니다. 전체 자동233개(67개 파일)와 타입/프로덕션 빌드를 통과했다.

Linux WebKit 자동 검사는 실제 iPhone/iPad Safari, 키보드·주소창 애니메이션과 발열/성능 검증을 대신하지 않는다. 실기기에서 회전·주소창·키보드·동시 조작을 다시 확인해야 한다. 새 서비스·저장 데이터·게임 규칙은 추가하지 않는다.
