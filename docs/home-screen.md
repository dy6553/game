# 메인 화면 통합 — 2026-11-07

사용자가 캐릭터 선택·무기 선택·게임 시작 버튼이 있는 메인 화면을 요청했다. 모드 카드에서 별도 출발 준비 창으로 이동하던 홈을 출격 설정 화면으로 바꿨다. 전투·점수·무기 성능·난이도·보급 규칙은 변경하지 않는다.

## 화면과 연결

- 왼쪽에 선택 캐릭터의 벡터 미리보기와 이름, 오른쪽에 소형 로봇/고양이형 로봇 선택을 표시한다.
- 권총/기관총/산탄총/저격총 선택 카드와 기존 WEAPONS에서 읽은 피해·탄창·재장전 수치를 표시한다.
- 봇 대전/온라인 대전/표적 연습 버튼, 봇 모드/난이도 선택, ‘게임 시작’ 버튼을 한 화면에 둔다.
- 봇1대1/개인전/생존/연습은 추가 준비 대화상자 없이 실제 선택 설정으로 바로 시작한다. PC는 선택적으로 ‘마우스 고정하고 시작’을 누를 수 있다.
- 온라인 시작은 같은 캐릭터·총을 온라인 로비에 전달하고 기존 방 만들기/친구 코드/자동 매칭을 선택하게 한다. 사람 대 사람 게임을 봇전처럼 즉시 시작했다고 표시하지 않는다.
- 홈 복귀 시 현재 경기의 모드·난이도·캐릭터·시작 총을 반영한다. 경기 중 획득한 무기는 시작 총으로 바꾸지 않는다. 기존 경기 중 출발 준비 대화상자는 유지한다.
- 홈의 개인 전적 진입 및 결과 창에서 홈/온라인 새 경기 복귀를 유지한다. 초대 링크는 모드 버튼 클릭에 의존하지 않고 온라인 로비로 직접 연결한다.
- 홈에서 전투와 입력은 정지한다. 자동 난이도는 생존에서만 선택 가능하고 타 모드로 전환하면 보통으로 정규화한다.

## 구조·미술

`src/home-screen.ts`가 메인 화면 마크업과 선택/설명 상태를 관리하고 `main.ts`는 실제 캐릭터/경기/온라인 로비를 연결한다. 선택 버튼은 aria-pressed로 상태를 표시하고 설명은 status 영역을 사용한다. 작은 화면은 세로 스크롤을 제공하고 가로 터치 화면의 시작 영역은 아래쪽에 고정한다. 캐릭터/무기 미리보기는 직접 작성한 인라인 SVG이며 실제 게임 모델을 새로 만들거나 외부 이미지를 다운로드하지 않는다. 새 패키지·서버·개인정보 저장은 없다.

## TDD·검증

`/tmp/harbor-home-red.log`에서 직접 시작 버튼 부재를 확인한 뒤 구현했다. `docs/qa/ui-flow.mjs`의 PC/모바일 대역 검사에서 캐릭터/산탄총/개인전/난이도 선택, 홈에서 전투 정지, 추가 창 없는 시작, 홈 복귀 선택 유지, 생존 자동 옵션 제한, 온라인 설정 전달과 기존 결과/전적 흐름을 확인한다.

전체108개(28개 파일) 실패0개. 타입/프로덕션 빌드 통과. 마지막 CSS 수정 후 프로덕션 빌드와 두 DOM 흐름을 다시 확인했다. 빌드의 기존500KB 청크 경고는 유지된다.

Chromium을 실제로 실행해 로컬 프로덕션 번들을 확인했다.1366×900에서 메인 시작 버튼 표시·캐릭터2/무기4·가로 넘침 없음, 고양이 로봇/산탄총/어려움 개인전 시작 후 HUD6발과 개인전·어려움 표시 및 준비 창 생략을 확인했다. 런타임 예외0개.844×390 터치 에뮬레이션에서 가로 넘침 없음을 확인했다. 모바일 시작 버튼이 처음에는 화면 아래에 있음을 구버전 화면에서 재현(`/tmp/harbor-home-mobile-red.log`)하고 시작 영역 sticky 배치를 적용했다.

브라우저는 헤드리스 Chromium/SwiftShader 소프트웨어 WebGL이다. 실제 GPU 성능·휴대폰 발열/FPS·물리 터치 검증으로 주장하지 않는다. 브라우저 검증 스크립트/스크린샷은 `/tmp/harbor-home-browser.mjs`, `/tmp/harbor-home-{desktop,mobile,mobile-start,mobile-final}.png`에 둔다.

모바일 고정 버튼 확인 결과: `/tmp/harbor-home-mobile-green.log`에서 화면높이390에 버튼하단374로 표시됨을 확인했고 `/tmp/harbor-home-mobile-final.png`를 검토했다. 스크롤 전에도 ‘게임 시작’을 누를 수 있다.
