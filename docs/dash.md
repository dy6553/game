# 대시 — 2026-11-07 사용자 승인

사용자가 온라인 실기기 검증을 뒤로 미루고 나머지 단계를 요청했다. PRD에 미정인 대시 수치를 질문했고 추천 규칙 승인을 받았다.

## 확정 규칙

PC F키/모바일 대시 버튼. 이동 중에는 이동 방향, 정지 상태에서는 수평 시점 방향으로4m를0.2초에 이동한다. 방향은 시작 순간 고정하고 대각선도 총4m다. 사용 시점부터3초 재사용 대기. 지상에서만 시작하며 대시 중 점프 불가. 사격·재장전은 기존대로 가능하고 무적/벽 관통을 추가하지 않는다. 기존 달리기와 별도다.

벽/가구/맵 경계는 기존 연속 충돌 하위 단계 계산을 사용한다. 충돌하면4m보다 짧게 이동할 수 있다. 사망 시 진행 중 대시를 멈추고 부활/새 경기에서는 초기 상태로 시작한다. 오프라인 메뉴/앱 전환은 남은 이동을 취소하고 재사용 시간은 게임 시간처럼 정지한다. 온라인은 서버 시간이 기준이며 이미 시작된0.2초 동작은 내 메뉴와 무관하게 서버가 끝낸다.

## 구조

- `src/dash.ts`: 승인 규칙, 방향 고정, 시간/거리/재사용 대기 계산. UI·네트워크와 분리한다.
- `src/input.ts`: F 단일 입력·반복/브라우저 Ctrl+F 제외·독립 터치 큐. pause/blur/resize/reset 시 해제한다.
- `main.ts`: 오프라인 대시 이동을 걷기와 중복 합산하지 않고 잔여 시간만 걷는다. 대시 버튼/카운트다운/점프 버튼 상태, 새 경기/부활/메뉴 처리를 연결한다.
- `network-game.ts`: 서버 DashState와 공유 advancePlayerMotion으로 이동/점프를 검증한다. dash 요청은 선택적 boolean으로 검증하고 기존 클라이언트 패킷은 허용한다. 거리/시간/무적/체력/서버 dash 상태를 클라이언트 값으로 받지 않는다. 입력 coalescing에서 단발 대시를 보존하고 처리 후 비운다.
- `online-motion.ts`: 서버와 같은 대시/점프 상태를 예측/재생한다. 대시 입력은 정상20Hz 간격을 기다리지 않고 즉시 전송한 뒤 예측해, 아직 안 보낸 이벤트가 수신 시 다시 시작되지 않게 한다. 보정·끊김·사망·부활 시 기존 중단/스냅 정책을 유지한다.
- 이전 서버에서 받은 상태에 dash 필드가 없으면 온라인 대시를 예측하거나 활성화하지 않고 ‘서버 준비 중’으로 표시한다. 서버 버전 헤더는 dash-v1. 서버/웹 배포 순서 차이에도 기존 경기는 유지한다.
- `server/check-dash.mjs`: 공개 또는 로컬 Worker의 private room과 실제 WebSocket 두 개로 거리/쿨타임/탄약체력/재접속/공중 요청 거절을 확인한 뒤 방을 종료한다. 공용 자동 매칭으로 실제 이용자와 만나지 않는다.
