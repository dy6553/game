# 관리자 레벨 편집

2026-11-08 사용자 승인. 지정한 관리자 계정만 계정 화면의 ‘관리자 · 레벨 편집’에서 이메일로 계정을 찾아 레벨을 변경한다. 최초 관리자 이메일은 비공개 설치 SQL에만 사용하며 공개 코드에 넣지 않는다.

## 사용

관리자는 계정 → 관리자 · 레벨 편집 → 이메일 입력/계정 찾기 → 레벨·선택 사유 입력 → 레벨 저장 순서로 사용한다. 입력한 레벨의 시작XP `(level−1)×200`으로 정확히 맞추므로 레벨을 낮출 수도 있다. 실제 서버 XP로 해금·봇 강화가 다시 계산된다. 레벨은1 이상의 정수와 안전하게 표현할 수 있는 경험치 범위 안에서 검증한다. 일반 계정의 승패·최근 공식 전적은 변경하지 않는다.

관리자 메뉴는 본인의 서버 역할이 확인된 경우에만 표시한다. 공개 전적 링크에서는 역할 필드가 있어도 숨긴다. 클라이언트 표시와 별도로 API에서 로그인 JWT→DB 관리자 멤버십을 매번 확인한다. 요청 본문의 관리자 플래그·이메일·계정ID를 호출자 신원으로 쓰지 않는다. 게임 UI에서 관리자를 임의 지정할 수 없다.

## 저장·동시 수정

`003-admin-levels.sql`은 역할·변경 영수증/감사 기록을 추가하며 기존 성장 초기화와 같은 트랜잭션에서 준비한다. RLS·PUBLIC 권한 회수와 profile FK를 사용한다. 최초 관리자는 Neon SQL Editor에서 지정 계정에 역할을 부여해야 한다. 배포만으로 누구에게도 권한이 생기지 않는다. SQL 실행 전에 해당 계정이 가입돼 있어야 한다. 실행 결과가0행이면 등록 여부/브랜치를 확인한다. 저장된 SQL 문서를 지워도 이미 등록한 역할/레벨은 유지된다.

조회 이후 XP가 달라지면409로 막고 다시 찾게 한다. 변경은 XP 갱신과 전후XP·시각·관리자·사유 기록을 원자적으로 저장한다. 요청UUID별 트랜잭션 advisory lock과 영수증으로 재전송을 한 번만 적용하며, 성공 응답을 잃은 뒤 재시도해도 이후 얻은XP를 덮어쓰지 않는다. 서버 역할도 트랜잭션 내부에서 재확인한다. 목록은 대상별 최근10건이며 사유는 textContent로 표시한다. 조회 이메일/인증 토큰은 저장하지 않는다.

대상 계정 삭제 시 그 계정의 변경 기록을 함께 지운다. 관리자 계정을 삭제하면 역할도 삭제되고 다른 대상에 남은 변경 기록의 관리자 참조는 비운다. 새로 같은 이메일로 가입해도 과거 관리자 역할이 복원되지 않는다.

## 설정 예시

아래 이메일은 예시다. 실제 관리자로 승인한 계정에만 운영 SQL Editor에서 한 번 적용한다. 이 SQL을 공개 게임 API로 실행하는 경로는 없다.

```sql
WITH owner AS (
 INSERT INTO harbor.profiles(subject)
 SELECT id::text FROM neon_auth."user"
 WHERE lower(email)='admin@example.com'
 ON CONFLICT(subject) DO UPDATE SET subject=EXCLUDED.subject
 RETURNING id
)
INSERT INTO harbor.admin_members(profile_id)
SELECT id FROM owner
ON CONFLICT(profile_id) DO UPDATE SET profile_id=EXCLUDED.profile_id
RETURNING '관리자 등록 완료' AS result;
```

## 검증 기록

TDD: 관리자 입력/레벨→XP/정산ID 및 이메일 검증의 assertion 실패2개를 먼저 실행하고 구현 후 통과했다. 관리자 UI 진입이 없는 상태에서 별도 화면 요구 실패를 실행한 뒤 역할별 메뉴·검색/저장·자기 성장 갱신·사유 HTML 비실행·충돌 재조회·복귀/닫기 정보 비움·일반 계정 차단을 통과했다. `tests/admin-levels.test.ts`, `tests/admin-worker.test.ts`, `docs/qa/admin-ui.mjs`.

PostgreSQL(PGlite)에서 실제 SQL로 일반 계정 거부·역할 비공개·정확 이메일 조회·XP/변경 기록 원자성·중복 재시도 후 추가XP 보존·동시 수정 한 건만 성공·역할 회수·계정 삭제를 확인했다. 기존 공식/성장 SQL 회귀도 검사했다. `docs/qa/admin-database.mjs`.

PC/모바일 Chromium1200×760/844×390은 합성 관리자 계정 응답을 사용한다. 운영 관리자 지정/편집과 별개이며, 운영 역할을 지정하기 전 실제 관리자 편집까지 완료했다고 표시하지 않는다. 최초 관리자 지정은 운영 DB 관리 연결이 없는 현재 환경에서 대신 실행할 수 없다. 배포 이후 실제 관리자 계정으로 새로고침해서 확인해야 한다.

최종 검증: 전체190개/51파일, 계정·가입·공개 전적 및 PC/모바일 DOM 흐름, 운영 설정 웹 빌드·Worker dry-run 통과. 실제 Chromium PC/모바일에서 관리자 검색→Lv6 저장→기록 표시→뒤로/일반계정 메뉴숨김을 통과했다. 최초 권한지정용 비공개SQL도 임시 PostgreSQL에서 대상1개/프로필생성/재실행 중복없음을 확인했다. 운영 관리자 지정은 아직 실행하지 않았다.
