# 온라인 대기방·닉네임·실시간 현황

2026-11-08 사용자 요청. 제안한 전원 준비/3초 카운트다운 대신 사용자는 ‘준비 없이 방장이 바로 시작’을 선택했다. 비회원은 연결 종료 시 이름 삭제·재접속 시 재입력 방식으로 확인했다.

## 방과 입장

- 방 만들기/코드 참가/자동 매칭은 별도 대기방으로 이동한다. 맵과 전투 조작을 숨기고3D 장면 그리기도 멈춘다. 대기방에 방 코드/복사·전장/모드·참가 닉네임/접속 상태·회원/비회원/방장 표시가 있다.
- 최소2명 접속(팀전은 양팀 접속) 시 방장만 ‘경기 시작’을 누를 수 있다. 준비 버튼이나 카운트다운 없이 함께 전장에 들어간다. 시작 전 사격·이동·획득·피해는 서버가 차단한다. 시작 시 참가자 위치를 다시 분산한다.
- 방장 대기 중 이탈/연결 종료 시 남은 접속자에게 방장을 넘긴다. 시작 전 나가면 자리/계정 예약을 지우고 재입장할 수 있다. 연결 복구 유예는30초, 만료 시 대기 참가자를 정리한다. 방 대기는10분까지 허용한다.
- 진행 중인 방에 들어온 사람도 먼저 별도 대기방을 보고 ‘진행 중 경기 참가’를 눌러 합류한다. 기존 경기와 기존 정원20명은 유지한다. 대기만 한 회원에게 전적/경험치를 정산하지 않는다.
- 기존 버전의 진행 경기/자동 테스트 fixture는 phase가 없으면 종전 규칙을 유지한다. 새 Worker가 생성하는 방은 항상 대기방 상태로 만든다.

## 닉네임

- 한글·영문 등 문자/숫자/공백/_/-를 사용해2~16자. NFKC 정규화와 앞뒤 공백 제거, 연속 공백 정리. 이메일·HTML·줄바꿈·보이지 않는 제어 문자는 허용하지 않는다. 같은 닉네임의 중복 사용을 계정 권한으로 취급하지 않는다.
- 신규 회원은 가입 화면에서 입력한다. 기존 회원은 첫 온라인 입장 시 설정하고, 계정 화면에서 변경할 수 있다. 이메일/인증ID를 닉네임으로 만들지 않는다. 변경은 다음 온라인 입장부터 적용한다.
- `/account/nickname`은 서버가 JWT를 확인한 본인 프로필만 변경한다.005마이그레이션으로 `harbor.profiles.nickname`을 추가한다. 기존 `DATABASE_URL`을 사용하는 서버 준비 단계에서 적용하며, 이름은 공개 프로필/온라인 표시명으로 사용한다. 클라이언트가 회원 이름/계정 ID를 위조해 예약할 수 없으며 서버가 실제 DB 이름을 읽는다.
- 비회원은 온라인 입장 전에 이름을 입력하고, 재접속 때도 새로 입력한다. 연결 종료/퇴장/새 페이지 이동 시 서버 상태와 클라이언트 표시에서 제거한다. 브라우저 저장소/쿠키/초대URL/Neon DB에 쓰지 않는다. Durable Object 체크포인트에서도 guest 이름을 제거한다. 방/세션ID와 점수는 기존 재접속 유예용으로 보존하지만 이름은 보존하지 않는다.
- 비회원 이름이 없는 재접속자는 입력 전 전투·대상 판정에서 제외한다. 회원의 이름을 비회원 메시지로 덮어쓸 수 없다. 명확한 회원/비회원 구분은 서버의 인증 결과를 사용한다.

## 전투 현황

- 팀전 왼쪽 패널: 아군/상대 팀의 현재 생존 및 접속 인원. 기존 부활 경기이므로 영구 탈락 수로 표시하지 않는다.
- 개인전: 킬 많은 순서·동점은 적은 데스 순서의 상위3명과 내 순위/성적. 전체 순위표에도 닉네임을 표시한다.
- 캐릭터 위: 닉네임과 작은 체력 막대. 아군 파랑/적 붉은 색을 사용하며, 벽 뒤/화면 밖/사망/연결 종료/대기 참가자의 이름표는 가린다.19개 DOM 풀을 재사용하고3D 텍스처나 글꼴 패키지를 추가하지 않는다. 조준 적 체력 카드에도 닉네임을 사용한다.
- 메뉴/대기방/홈/결과에서는 관련 현황/이름표를 숨기고, 종료 시 숨은 목록의 이름 텍스트까지 비운다.

## 검증

대기방 전투 정지·방장 시작·방장 양도·자리 재사용을 Red→Green으로 구현했다. 실제 Worker의 메시지 처리에서 비방장 시작 위조를 차단하고 체크포인트에 guest 이름이 없음을 확인했다. 회원 이름 조작 메시지도 차단한다. 기존 전적·XP는 실제 참가한 회원만 기록한다.

실제 소켓 종료 시험에서 종료 응답이 없어 CLOSING 상태에 남는 문제를 재현했다(2초 이내 종료 실패). 서버 종료 응답과 재진입 방지를 추가한 뒤 브라우저의 강제 게임 소켓 종료→재접속→새 닉네임 입력→상대 순위에 새 이름 표시까지 통과했다. 브라우저 두 개의 이 흐름 검사는 클라우드 소프트웨어 GPU 부담을 줄이기 위해3D 그리기만 테스트 응답에서 생략했고 서버/화면/입력/소켓은 실제 경로를 사용했다. 실제3D 이름표 위치/HP/벽 차폐/대기 숨김은 별도 Babylon 장면 검사로 통과했다. QA 주입은 배포 소스에 없다.

로컬 실제 Worker 개인전20개·팀전20개 접속→대기 상태→방장 시작→21번째 거절→한 명 이탈 후 진행을 확인했다. 실제 PostgreSQL(PGlite)에서 회원 이름 저장/새 연결 재조회·잘못된 이름 거부·타 계정 불변과 기존20명 전적·XP중복 방지 검사를 통과했다. 가입/계정 화면·PC/모바일 DOM 흐름 회귀도 통과했다. 최종 전체/빌드/공개 배포 결과는 인수인계에 기록한다.

추가 유료 서비스/패키지/새 개인정보 공급자 없음. 물리 휴대폰 여러 대·Safari/서로 다른 인터넷에서 장시간 재접속 검증은 별도다.
