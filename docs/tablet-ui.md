# 태블릿 조작키·게임 UI 정리

2026-11-08 사용자 요청. 휴대폰 조작키 크기는 유지하고 태블릿의 작은 터치 UI를 확대한다. 홈/선택창/계정/일시정지 등은 일관된 게임 스타일로 정리한다. 화면의 프레임 통계는 제거한다.

## 조작과 화면 크기

터치 가능·가로·너비900px 이상·높이600px 이상을 태블릿 레이아웃으로 적용한다(CSS px). 조이스틱150~200px, 사격100~128px, 점프/재장전/확대72~94px, 달리기/대시80×62px, 무기 슬롯 높이48px 이상이다. 버튼 간 간격과 안전 영역을 따로 계산해 서로 겹치지 않게 배치한다. 조이스틱은 기존 입력 코드가 실제 DOM 크기로 정규화하므로 이동 속도/감도 규칙을 바꾸지 않는다. 휴대폰은 기존 조이스틱104px·사격74px·점프/재장전/확대54px를 유지한다.

홈은 실제3D 캐릭터를 중심에 유지하며 장비와 출격 설정을 양쪽에 배치한다. 성장 상세 안에 숨겨져 있던 전장 선택을 출격 패널로 옮겨 즉시 접근하게 한다. 선택한 전장 이름/설명도 함께 바뀐다. 성장 요약은 레벨/총XP만 보여주고 다음 레벨/강화/해금 설명은 펼쳐서 본다. 무기 수치 표시는 소수 둘째 자리까지 정리하지만 전투 수치는 그대로다.

공통 테마 `src/ui-theme.css`로 메뉴·계정·선택·전적·정지 화면의 패널/색/간격/입력/버튼 상태를 통일한다. 중복 영어 표식과 장식을 줄이고 출격 버튼의 대비를 높였다. 게임 중 설정은 모든 화면에서 메뉴 버튼으로 열어 화면을 덜 가린다. 좁고 짧은 화면은 패널 내부 스크롤과 출격 버튼 고정으로 접근을 유지한다. 게임 규칙·계정/관리자 권한·DB·서버 코드는 바꾸지 않는다. 추가 에셋/패키지/서비스는 없다.

## 프레임 표시

임시 `performance-hud.ts`와 main의 생성/갱신, 관련 CSS·도움말 설명을 제거했다. 자동 화질 조절은 그대로 작동하며 명시적으로 켜는 기존 진단 도구는 유지한다. 정상 게임 화면에는 FPS/P95/끊김 표시가 없다. 클라우드 UI 검사로 실기기 FPS/발열 개선률을 주장하지 않는다.

## 검증

TDD: 실제 Chromium에서 수정 전 태블릿 조이스틱150px 미달, 접힌 성장창 때문에 전장 선택 숨김, main에 성능 표시 생성/갱신 잔존을 각각 assertion 실패로 확인했다. 최소 구현 후 Green과 기존190개/51파일 회귀를 통과했다.

`docs/qa/ui-layout.mjs`는740×320/740×360/844×390 휴대폰,1024×600/1280×800 태블릿,1440×900 데스크톱에서 출격 버튼 화면 내 배치·전장 선택 즉시 노출·폰 크기 유지·태블릿 크기 확대·조작키 간 비중첩·프레임 표시 제거를 검사한다. 실행에는 개발 서버, 선택 설치된 Playwright와 Chromium이 필요하며 HARBOR_UI_URL/CHROMIUM_PATH/HARBOR_BROWSER_MODULE로 경로를 바꿀 수 있다.

기존 PC/모바일 전체DOM, 회원가입/공개 전적/관리자UI와 운영 빌드도 검사했다. 실제 게임3D 브라우저 결과와 운영 배포 결과는 릴리스 기록에서 구분한다. Android/iPad 실기기에서 손가락 도달 범위·물리 크기는 별도 수용 사항이다.

실제3D 게임 Chromium에서도1280×800 태블릿·844×390 휴대폰·1440×900 PC의 홈/전장 선택/출격/메뉴/도움말 흐름과 화면 예외0건을 확인했다. 태블릿의 큰 조이스틱을 누른 채 사격→사격 손가락만 해제해도 이동 유지→이동 손가락 해제 시 정지를 검증했다. 정상 화면의 performance-hud 노드0개를 확인했다. 실제 단말 수용과 별도로 클라우드 브라우저 수용을 완료한 것이다.
