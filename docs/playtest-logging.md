# 플레이 성능 진단 수집 — 2026-11-06

사용자는 플레이 로그를 수집해 수정 필요 여부를 판단하도록 요청했고, 이후 실제 체감이 괜찮다고 보고했다. 추가 이동/전투 수정은 보류하고 진단 기능만 추가한다. 이미 끝난 플레이는 이 기능 배포 전이므로 수집된 것으로 주장하지 않는다.

## 범위와 이용

https://project-3uu6s.vercel.app/?diagnostics=1 에서만 수집한다. 일반 주소에서는 전송하지 않는다. 우측 하단에 진단 코드·수집 상태·중지·기록 저장 버튼을 표시한다. 15초 단위 요약을 최대10분/40건 전송한다. 메뉴·도움말·비활성 구간을 제외하며 모드별로 구분한다. 앱 전환/페이지 종료 시 남은 요약을 keepalive로 전송하지만 종료 전송 성공은 보장하지 않는다.

기록: 프레임수·활성시간·FPS·프레임P95·50ms초과 프레임수, 입력확인 왕복시간 중앙값/P95/최댓값, 상태 수신간격P95/최댓값, 위치 보정량P95와 표본수. 브라우저 실행별 무작위8자리 진단코드로 묶으며 계정·IP·사용자에이전트·화면녹화·키/조준입력·위치좌표·방코드·접속토큰은 앱 로그에 넣지 않는다. 호스팅 서비스 자체 접근 로그는 별도 정책을 따른다.

기존 Vercel Functions /api/playtest를 사용한다. 같은 Origin, POST,4KiB 이하, 허용 필드·형식·수치 범위만 처리하고 console.log의 harbor_playtest 행으로 남긴다. source=synthetic은 배포 검증용으로 실제 플레이 판단에서 제외한다. 공개 쓰기 API에 인증 계정을 추가하지 않으므로 진단 기록은 클라이언트 보고이며 공식 경기 결과나 보안 증거로 취급하지 않는다.

## 비용·보존·조회

추가 DB·로그 업체·유료요금제를 만들지 않는다. 기존 Vercel 무료 Functions 및 Runtime Logs 한도를 사용한다. 사용자 테스트 한 번 최대40회 호출이다. 무료 한도 초과 시 요금제를 바꾸지 않고 수집을 중단/실패 처리한다. API 실패는 게임 실행을 막지 않으며 로컬 ‘기록 저장’으로 대체할 수 있다.

Vercel Runtime Logs Hobby 조회 범위는 대략 최근1시간이므로 장기 보존을 보장하지 않는다. 무료 한도/로그 조건 근거: https://vercel.com/docs/logs/runtime 및 https://vercel.com/docs/functions/limitations . 테스트 후 즉시 사용자 ‘끝났어’ 메시지에 따라 연결된 get_runtime_logs 도구로 projectId=prj_x8fO0gOkbYACT3ty6JE6Ldp5Hs1x, teamId=wonhee3, query=harbor_playtest, since=30m을 조회한다. 세션의 진단코드로 좁히고 synthetic은 제외한다. 대화가 끝난 뒤 자동으로 감시하거나 사용자에게 연락하는 기능은 없다.

## 판단

여러15초 구간을 함께 본다. 높은 RTT·큰 수신 공백과 안정적인 FPS이면 통신/배치 조사, 낮은 FPS·높은 프레임P95와 정상 RTT이면 렌더/기기 조사, 큰 보정이 반복되면 동기화 조사 대상으로 삼는다. 표본 부족·로그 없음은 정상 판정으로 취급하지 않는다. 실제 체감이 괜찮고 수치상 반복 문제가 없다면 추가 수정은 보류한다. 진단 판단 기준을 제품의 확정 성능 목표나 특정 FPS 보장으로 취급하지 않는다.
