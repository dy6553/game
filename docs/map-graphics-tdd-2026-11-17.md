# 그래픽 고·중·저 렌더링 회귀 검사 — 2026-11-17

사용자가 건물 표시가 정상으로 돌아왔다고 확인한 뒤, 설산·달기지의 그래픽 고·중·저를 TDD 방식으로 검사하도록 요청했다. 정상 동작에 임의의 제품 변경을 추가하지 않고, 잘못된 표시 상태를 테스트 장면에서 재현해 검사 자체가 오류를 잡는지 검증했다. 이 재현은 사용자 기기에서 발생했던 원인을 확정하는 진단은 아니다.

## Red → Green

`tests/map-render-profiles.test.ts`에서 설정 문자열뿐 아니라 다음을 검사한다.

- 활성화되고 실제 정점·법선·색 데이터를 가진 외형이 존재하는지
- 판정용 지면·벽 상자가 렌더링에 노출되지 않는지
- 공유 충돌 벽 위치에 실제 외형 삼각형이 있는지
- 로비·일시정지·초기화·온라인 표시·반복 그래픽 전환 뒤에도 외형과 판정이 유지되는지

Red는 두 가지 별도 결함 재현으로 확인했다.

```
TEST_MAP_RENDER_FAULT=hide-art node --test --test-isolation=none --test-name-pattern='keeps visible' tests/map-render-profiles.test.ts
TEST_MAP_RENDER_FAULT=show-colliders node --test --test-isolation=none --test-name-pattern='keeps visible' tests/map-render-profiles.test.ts
```

외형 숨김: 6개 조합 모두 assertion 실패. 판정 상자 노출: 6개 조합 모두 assertion 실패. 실패 지점이 각각 의도한 가시성/판정 노출 검사임을 확인했다.

결함 재현 플래그 없이 실행한 Green: 6개 조합과 두 맵의 상태 전환 검사, 총 8개 통과. NullEngine은 GPU 검사 도구가 아니므로 재질의 GPU 준비와 실제 그리기 단계는 별도 브라우저 검사로 구분했다.

## 실제 렌더링

브라우저에서는 배포와 같은 최적화 JS를 실행하고, 실제 로비·환경설정에서 맵과 그래픽을 선택한다. 검사 브라우저에서만 프런트엔드 맵 해금을 적용하며 서버 인증을 변경하지 않는다. 맵 생성기·재질·렌더 구현은 그대로 사용한다.

WebGL 1/2 각각에 대해 설산·달기지 × 저·중·고, 총 12개 조합에서 다음을 확인한다.

- 선택한 그래픽과 활성 맵 외형 상태의 일치
- GPU 재질 준비 완료
- 맵 메시가 실제 그리기 단계에 도달
- 판정용 상자 비표시
- 화면 캡처와 페이지 실행 오류 수집

자료는 `/workspace/qa/map-quality-tdd/`의 JSON·PNG·로그에 저장한다. 물리 삼성 태블릿의 GPU나 FPS를 측정한 결과가 아니며, WebGL 모드를 나누어 검사한 Chromium 결과다.
