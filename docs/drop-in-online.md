# 개인전·팀전1명 시작과 경기 중 합류 — 2026-11-09

사용자는 최대20명을 최소 인원으로 기다리지 않고 현재 참가자끼리 시작하며, 경기 중에도 순서대로 합류하도록 요청했다. 기존 별도 대기방·준비 없이 방장이 시작하는 흐름은 유지한다.

개인전/팀전은 닉네임 확인을 마친 접속자1명부터 방장이 시작할 수 있다. 시작 전에는 이동/사격이 차단된다. 시작 후 혼자이거나 한 팀만 남아도 조작/보급/경기가 계속된다. 상대가 없다는 이유로 자동 승리나 경험치를 주지 않는다. 기존 개인전10킬·팀30킬과20명 정원,1대1의2명/상대 연결 대기·복구 규칙은 유지한다.

진행 중 방의 예약은 아직 참가로 정산하지 않는다. WebSocket 세션 인증을 마치면 서버가 즉시 deploy하여 전장에 합류시키며 닉네임이 없는 비회원은 유효한 이름을 다시 설정한 뒤 자동 합류한다. 초대/자동 매칭의 중도 입장에 별도 참가 버튼이 필요 없다. 기존 참가자의 점수·보급·진행을 초기화하지 않고 새 참가자는 기존 분산 생성·3초 보호(사격 해제)를 사용한다. 구형 deploy 명령도 호환한다.

진행 중 방 코드가 로비 메타데이터의10분 보관 기간 때문에 막히지 않도록 실제 Room이 join 예약 가능 여부를 판정한다. 존재하지 않거나 닫힌 Room의 join 요청은 예약을 만들지 않고404를 반환한다. 정원이 찼거나 승자가 정해진 방은409를 반환한다. 원래JWT·계정 중복·폐공장/Lv3·캐릭터 해금 검증을 계속 적용한다.

개인전/팀전의 자동 매칭 후보는 시간만으로 버리지 않고 다음 요청 때 Room의 실제 상태로 검증한다. full/finished면 기존 방식으로 새 방을 만든다. 후보 포인터는2모드×2맵의 제한된 키이며 포인터 보관이 빈 Room의 게임 tick을 유지시키지는 않는다. 모든 소켓이 닫히면 타이머 정리와 기존 알람 정리를 계속 사용한다.

TDD:1명 host start, 인증 후 중도 socket 자동deploy, 오래된 로비 메타데이터의 live room join과 quick 후보 유지가 실패하는 것을 확인한 뒤 수정했다. join 보호를 Room으로 옮기기 전에 알 수 없는 코드가 예약을 만드는 실패200vs404도 확인했다. 기존 FFA에서 상대가 끊기면 정지한다는 기대값을 새로운 사용자 규칙에 맞춰 수정했다. 장비 피해/회복/사망/부활/재접속 검사는 유지한다.

검증:1/2/5/19/20명 시작과21번째 거부,1대1 최소2명 유지, 이름 미확정 중도 참가 차단/유효 이름 후 참가·guest 이름 체크포인트 미저장, 혼자 남은 방의2분 인원부족 종료 방지, 코드/quick 발견을 검사한다. 실제 소켓에서는 개인전·팀전 각각1명 시작 후 진행 중19명을 순차 합류시키고 구형1명/신형19명 프로토콜, 입력ACK·개인 인벤토리·잘못된 명령 거부를 확인한다. `docs/qa/network-load.mjs`는 ONLINE_BASE로 로컬/공개 서버에 재현한다. 실제 모바일 Chromium에서 개인전·팀전의1명 시작 버튼·혼자 사격·실행 중 소켓/브라우저 자동 합류를 통과했다. 전체 자동257개/70파일, PC/모바일 DOM 흐름, 운영 설정 타입/웹 빌드와 Worker dry-run을 통과했다. 실기기 네트워크/성능은 별도 확인이 필요하다.
