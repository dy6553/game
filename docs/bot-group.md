# 봇 3명 개인전 — 2026-11-06

## 사용자 확정

봇3명과 총4명이 먼저10킬을 경쟁하는 모드를 요청했다. 세부 질문에서 사용자는 ‘봇은 플레이어만 공격’을 선택했다. 따라서 이름은 개인전이지만 봇끼리 교전하는 방식은 아니다. 나와 각 봇의 점수를 따로 기록하고 어느 한 명이10킬이면 즉시 종료한다. 봇3명은 같은 선택 난이도·권총·체력100·피해25·3초 부활을 사용한다. 기존 경고/조준/회피·엄폐·탄약/재장전/발사 간격을 유지한다. 플레이어는 기존 시작 총과 상자·최대3개·교체·사망 시 시작 총 복구를 유지한다.

## 구현

홈 → 봇 대전 → 게임 모드 ‘봇 3명 개인전’. 시작 화면에 봇은 나만 공격한다는 설명을 표시한다. 쉬움/보통/어려움 선택, 메뉴 변경과 재시작, 일시정지 흐름을 제공한다.

봇1 빨강, 봇2 파랑, 봇3 노랑 머리 위 표시와 개별 체력/점수판으로 구분한다. 각 메시의 botId로 피해 대상을 정하고 처치를 한 번만 반영한다. 처치된 봇은 피격 대상에서 제외하고 해당 봇의 쓰러짐·처치 효과를 보여준다. 모델과 효과는 추가2세트를 최초 입장 때 한 번만 만들고 재시작/모드 전환에서 재사용한다. 낮은 화질의 효과 제한을 각 봇에도 적용한다.

createBotMatch는 기존 createDuel의 난이도·AI 이동/조준·탄약을 에이전트별로 재사용하면서 플레이어 공통 체력/사망과 개인별 점수를 관리한다. 봇의 사격 callback이 실제 벽에 막혔거나 경고 위치에서 플레이어가 피했으면 피해를 주지 않는다. 플레이어 사망 중 살아 있는 봇은 타깃 없이 이동/조준을 멈추되 재장전과 죽은 봇의 부활 시간은 진행한다.

초기 위치는 플레이어(0,-8), 봇(0,18),(-24,0),(24,0). 부활은 지도에 설계한10개 후보 중 공통 canStand 충돌 검사를 통과한 지점에서 살아 있는 다른 캐릭터들과 최소 거리가 가장 큰 곳을 고른다. 후보상 최대 거리 선택이며 전체 지도 최적 위치나 적 시야 밖을 보장하지 않는다. 무적 시간을 추가하지 않는다. 플레이어 부활 시 실제 위치·카메라와 인벤토리를 함께 초기화한다. 마지막 타격의 봇에게 해당 킬을 한 번 부여하며 경기 종료 후 추가 피해/점수를 막는다.

## TDD와 검증

먼저 tests/bot-group.test.ts를 작성하고4개 실패를 실행으로 확인했다. 기존 duel 모듈에 다인전 컨트롤러가 없다는 단언3개와 실제 장면 setMode('ffa')가 전투로 처리되지 않는 단언이 실패했다. UI도 설정에 ffa 선택지가 없어 실패했다. 모듈 경로/설치 오류를 Red로 삼지 않았다.

최소 구현 후4개가 통과했다. 추가 실제 장면 회귀2개로 봇2/3의 개별 광선 피격/점수, 반복 모드 전환의 메시/재질 개수 고정, 실제 플레이어 사망·먼 지점 부활·시작 총만 복구를 확인해 총6개 통과했다. 추가3D회귀 후 한 프로세스의 전체 실행이 약2GB 힙 한도로 중단되어 scripts/run-tests.mjs로 파일별 순차 프로세스 실행을 도입했다. 힙 한도를 올리거나 실패를 무시하지 않으며 어느 파일이라도 실패하면 npm test는 실패한다. 분리 실행한 전체 자동80개, 타입/프로덕션 빌드, PC/모바일 DOM의 모드 선택·3명 점수 표시·난이도·시작 설정 왕복 검사 통과. 기존1대1·온라인 규칙·무기획득·점프/기울어짐 회귀 검사도 유지한다.

실제 GPU 화면·휴대폰 프레임/발열/체감 난이도와 실제 두 손 터치 배치는 미측정이다. 새 외부 서비스·유료 리소스·새 에셋을 추가하지 않았다. 온라인3명 대전·봇끼리 전투·웨이브 생존·자동 난이도는 이번 구현이 아니다.
